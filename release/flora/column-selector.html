Proposed author-overlap rule

This is a proposal for enrichment, not an implemented data correction.

  • A structured entry with a family name can participate in surname matching, even if given is absent. A missing first name alone does not imply a consortium.
  • An entry with a literal name, but no given or family, is a collective-or-unresolved candidate. Count such entries as byline entities for a quality flag, not as a known number of people. A name could also be an unparsed individual.
  • Entries with only given, no name fields, invalid JSON, or an unusable list are also unresolved. Organisation-like text in other fields can be flagged for review, but missing fields are not proof of a consortium.
  • If either list contains an unresolved/collective entry, publish missing for both overlap measures under the conservative rule, including mixed individual/group lists. Never silently discard the group and report a definitive zero or percentage.
  • Otherwise retain the documented surname proxy. A positive count is a match of names, not verified identity; homonyms remain possible. No automatic expansion of consortium membership is needed.

The three known zero-valued collective-only cases still need a pipeline/correction-log fix. No release CSV values are edited by this selector.
